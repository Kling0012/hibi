uv run --no-project --python 3.12 --with pyyaml --with loguru python tests/repro_capture_pause.py

環境は Linux、Python 3.12.15、Node.js 22.23.2、PyYAML 6.0.3。Node.js は標準の型除去と VM Modules を使うため、実験的機能の警告を出す。

## 修正前の結果

上のコマンドは終了コード 1、`Ran 13 tests`、`FAILED (failures=9)` で終了した。実行時エラーはない。Python 側の 12 ケースは 4 件成功、8 件失敗。残る 1 ケースは Node.js の実行結果を確認するもので、Node.js 側の 5 ケースは 2 件成功、3 件失敗だった。

- フレームを受け付けてから一時停止を保存し、`_push_loop` を進めると、`live_stream_frame` が合成画像付きで 1 回呼ばれた。
- exact トリガーを入れてから一時停止を保存し、`_summarizer_loop` を進めると、`generate(route="exact")` が画像付きで 1 回呼ばれた。
- interval トリガーも一時停止後に `live_ask` を 1 回呼んだ。interval は画像を直接渡さず、既存の Live セッションに要約を求める経路である。
- 一時停止を保存しても、フレームと exact トリガーの待機件数はそれぞれ 1 件のままだった。期待値は両方 0 件。
- 一時停止を保存した後、再開を保存してから処理を進めると、停止前の Live フレーム、exact トリガー、interval トリガーが処理された。
- `_handle_frame` が設定を読んだ後、画像ハッシュを計算する時点で一時停止を保存しても、未開始だった Live 呼び出しに画像が渡った。
- Electron は起動時から `paused=true` でも、タイマー 1 回で取得とローカル送信をそれぞれ 1 回実行した。期待値は両方 0 回。
- Electron の稼働中に `paused=true` へ変更すると、次のタイマーでも取得とローカル送信が各 1 回増えた。
- Electron が取得を始めた後、ローカル送信を始める前に一時停止しても、ローカル送信が 1 回実行された。

初回の実行では、再現スクリプトの依存読み込みとキュー操作にエラーがあった。スクリプトだけを修正して再実行し、上記の結果を確認した。

対照ケースでは、バックエンドの停止中の新規受付拒否と、停止していないときの Live・exact・interval 呼び出しが成功した。Electron も通常の取得・送信と、離席による取得・送信の停止が成功した。exact の対照ケースでは、渡された画像が合成データの base64 と一致することも確認した。

## 再現方法と限界

Python は実際の `ScreenLiveMonitor` と `ConfigManager` を読み込み、設定ファイルを一時ディレクトリへ保存して再読込する。グローバル設定の参照先だけをこの設定へ差し替える。画像のハッシュ計算とプロバイダーはモックに置き換える。バックグラウンドスレッドは起動せず、実際の処理ループを同期的に 1 件進める。

Electron は実際の `LiveCaptureService.ts` の型を除去して VM で実行する。タイマー、`desktopCapturer`、axios、ウィンドウ情報をモックに置き換える。設定取得のモックは、その時点の `capture.paused` を返す。現在の実装がその値を参照しないことを実行で確認した。

未送信の確認は、プロバイダーのモックがまだ呼ばれていない時点で一時停止し、その後に呼ばれるかを調べた。送信開始後の取り消しは検証していない。

未実行: 設定 HTTP API を通した保存、アプリ全体の起動、実画像取得、外部 AI 通信、実機 E2E、全テスト。今回の工程はモックによる再現であり、実画像と外部送信を使わない指定に従った。全テストはこの工程の対象外。
